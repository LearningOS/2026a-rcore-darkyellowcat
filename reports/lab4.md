# chapter6 与 chapter7 练习

## 功能总结
本章实现了文件状态查询与硬链接管理。
`fstat` 获取 inode 编号、文件类型和链接数，支持跨页写回；
`linkat` 让多个文件名共享同一 inode；
`unlinkat` 删除目录项，并在链接数和打开对象数均为零时回收 inode、数据块及索引块。
同时复用空目录槽，保留文件删除后已打开描述符的访问能力，并将前章的时间、内存映射和进程创建功能适配到 Ch6。

## ch6问答作业

### 在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？

根索引节点是文件系统的根节点，负责表示根目录，
访问文件时，文件系统从 root inode 开始，根据路径逐级查找目录项，最终找到目标文件对应的 inode。

文件系统无法正确读取 root inode，
无法通过目录树找到对应的 inode 而无法正常访问，使得文件系统无法使用。

## ch7问答作业

### 举出使用 pipe 的一个实际应用的例子。

执行由一URL标示的万维网资源的一种拼写检查器：

```
// wiki
curl "https://en.wikipedia.org/wiki/Pipeline_(Unix)" | \
sed 's/[^a-zA-Z ]/ /g' | \
tr 'A-Z ' 'a-z\n' | \
grep '[a-z]' | \
sort -u | \
comm -23 - /usr/share/dict/words | \
less
```

将前一个命令的输出通过“管道”导入到接下来的一行命令作为输入。

### 如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐，请设计一个更易用的多进程通信机制。

pipe 本身是半双工的，互相通信只能通过两个管道实现。

为了解决这个问题，可以考虑引入消息队列。

发送者将消息发送到消息队列中，接收者从消息队列中读取消息。这样可以实现多进程之间的通信，而不需要为每一对进程建立一个管道。
